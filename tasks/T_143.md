# T_143: Make packaged PDF canvas loading reliable

## Status

Done

## Summary

Fix AI PDF import in the Windows portable build when loading `@napi-rs/canvas` fails with an
`ENOENT` for `resources/app.asar.unpacked/node_modules/@napi-rs/canvas/index.js`, even though the
published executable contains the canvas wrapper and native binding.

## Acceptance Criteria

1. PDF import in a packaged Windows build does not depend on the canvas JavaScript entry point
   remaining available in the portable executable's temporary extraction directory.
2. The platform-specific native canvas binding remains unpacked and loadable by Electron.
3. Ordinary image imports continue to work without requiring canvas.
4. Automated tests cover the packaged canvas loading strategy and existing PDF import behavior.
5. A Windows package inspection confirms the JavaScript wrapper is available from `app.asar` and
   the native `.node` binding is present under `app.asar.unpacked`.
6. Tests, lint, build, and Electron main-process syntax checks pass.

## Implementation Notes

- Prefer keeping the JavaScript portion of `@napi-rs/canvas` inside `app.asar` and unpacking only
  the platform-native binding package. This avoids a late lazy `require()` of JavaScript from the
  portable launcher's temporary directory while preserving Electron's native-module requirement.
- Add a package-configuration contract test so future ASAR rule changes cannot silently reintroduce
  the failure.

## Verification

- `npm run test` passes (65 files, 591 tests), including the new Electron packaging contract and the
  real textless-PDF canvas test.
- `npm run lint` passes.
- `npm run build` passes.
- `node --check` passes for `electron/main.cjs`, `electron/preload.cjs`, and
  `electron/documentImport.cjs`.
- `electron-builder --win --x64 --dir` passes in a disposable output directory.
- ASAR inspection confirms `@napi-rs/canvas/index.js` and `js-binding.js` have packed offsets and are
  not present externally; the Windows native `.node` binding is marked unpacked and exists externally
  at 27,294,720 bytes.
- Running the packaged `Nexus.exe` with `ELECTRON_RUN_AS_NODE=1` successfully requires the canvas
  wrapper from `app.asar`, loads its unpacked native binding, creates a canvas, and emits a PNG data
  URL.
