# T_144: Add AI Content Organization

## Status

Done

## Summary

Add a document-level AI action named **Content Organization** that cleans up and restructures the
current document without changing its meaning or introducing new content. It may reorganize existing
sections, normalize Markdown structure and spacing, repair extraction/OCR line breaks, and remove
obvious non-semantic pagination artifacts.

## Proposed Behavior

- Add **Content Organization** to the AI menu alongside the existing document actions.
- Send the current document through the configured AI provider using a purpose-built organization
  prompt.
- Preserve every piece of semantic content. The model must not summarize, paraphrase, invent facts,
  remove substantive sentences, or change the meaning of the document.
- Allow structural cleanup: reorder existing material into coherent sections, normalize headings and
  lists, improve paragraph boundaries and whitespace, and repair formatting introduced by scraping,
  OCR, or PDF extraction.
- Allow removal only of obvious non-semantic artifacts such as standalone page numbers and repeated
  page headers or footers. Ambiguous text must be retained.
- Preserve frontmatter, links, image data URLs, code, math, tables, footnotes, directives, and Nexus
  embedded-document fences without altering their payloads.
- Apply the result as one undoable document replacement. Cancellation, provider failure, or invalid
  output leaves the document unchanged.
- Reuse the existing AI progress, cancellation, provider capability, and error-reporting behavior.

## Acceptance Criteria

1. The AI menu exposes a **Content Organization** action for a non-empty document.
2. Invoking the action sends the complete current Markdown to the configured AI provider with clear
   preservation and cleanup constraints.
3. The result may reorganize and reformat existing content and remove only clear pagination artifacts;
   it must not intentionally add, summarize, paraphrase, or remove semantic content.
4. Protected Markdown payloads such as code, math, images, links, frontmatter, and embedded Nexus
   blocks are explicitly preserved by the prompt and output-processing path.
5. A successful result replaces the document in one undoable operation; cancellation and failure are
   non-destructive.
6. Automated tests cover the prompt contract, action availability/dispatch, successful replacement,
   cancellation, and failure behavior.
7. Product, architecture, and changelog documentation are updated; tests, lint, and build pass.
